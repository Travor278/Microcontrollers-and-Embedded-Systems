### 3.2 放置步骤
1. **F1**:菜单 P → 输入 `STM32F103C8` → 双击放在画布中央
2. **F2**:依次拖入 2 个晶振,放在 MCU 左侧
3. **F3**:在晶振两端各加 22pF 电容,接 GND
4. **F4**:NRST 引脚(7 脚)接 10kΩ 上拉到 3.3V,并接复位按键到 GND
5. **F5**:BOOT0(44 脚)接 10kΩ 下拉到 GND
6. **F6**:每个 VDD 引脚(24/36/48)旁加 100nF 退耦电容到 GND
7. **F7**:VDDA(9 脚)单独加 4.7μF 电解 + 100nF 并联到 GND
8. **F8**:任选 GPIO(如 PC13,2 脚)接 LED + 1kΩ 限流到 GND

## 五、子电路 ③ 燃气电磁阀关阀控制(本设计核心安全电路)

### 5.1 元件清单
| # | 元件 | Proteus 关键词 | 数量 | 参数 |
|:--:|---|---|:--:|---|
| 1 | 光耦 | `PC817` 或 `4N25` | 1 | 隔离 |
| 2 | NPN 驱动三极管 | `S8050`(或 `2N2222`) | 1 | 驱动继电器 |
| 3 | 继电器 | `RELAY-DPDT` | 1 | 24V 线圈 |
| 4 | 续流二极管 | `1N4007` | 1 | 反并联继电器线圈 |
| 5 | 光耦 LED 限流 | `RES` | 1 | 1kΩ |
| 6 | 基极电阻 | `RES` | 1 | 4.7kΩ |
| 7 | 基极下拉 | `RES` | 1 | 10kΩ |
| 8 | 直流电机(代替电磁阀) | `MOTOR-DC` | 1 | 视觉表示阀门动作 |
| 9 | 5V/24V 电源 | `POWER` | 2 | 标签 +5V / +24V |

### 5.2 设计要点(关键讲解)
1. **光耦隔离**:STM32 的 3.3V GPIO 不能直接驱动继电器(电流不够 + 反向冲击会烧 MCU),必须**光耦电气隔离**
2. **续流二极管 1N4007**:继电器线圈是电感,断电瞬间产生反向高压,会击穿三极管。**1N4007 反并联吸收**
3. **NC 常闭阀**:实际选用断电自动关闭的常闭型阀,**Fail-Safe** 设计——即使整机断电也安全
4. **手动复位**:阀体支持机械复位,避免误触发后锁死

### 5.3 接线表
| 信号源 | → | 信号终点 | 备注 |
|---|:---:|---|---|
| STM32 PC0 | → | PC817 引脚 1 (LED 阳极,经 1kΩ) | 控制信号 |
| PC817 引脚 2 (LED 阴极) | → | GND (MCU 侧) | |
| PC817 引脚 4 (光晶 集电极) | → | +5V (执行侧),经 10kΩ 上拉电阻 | 光晶为开漏输出:截止时被上拉至 5V,饱和时被拉低至 ≈0V |
| PC817 引脚 3 (光晶 发射极) | → | GND (执行侧) | 发射极接执行侧地 |
| PC817 引脚 4 (集电极信号) | → | 4.7kΩ → S8050 基极 | 取集电极作为驱动信号 |
| S8050 基极 | → | 10kΩ → GND | 防误触发下拉 |
| S8050 集电极 | → | 继电器线圈一端 | |
| 继电器线圈另一端 | → | +24V | 线圈电源 |
| 继电器线圈两端 | — | 1N4007 反并联 (阴极接 +24V) | 续流保护 |
| S8050 发射极 | → | GND (执行侧) | |
| 继电器常开触点 COM | — | +24V (供阀电路) | |
| 继电器常开触点 NO | → | DC 电机正极 (代表阀线圈) | 仿真用 NO 触点演示动作;真实产品 NC 阀正常通电保持开启,断电时自动关闭 (Fail-Safe) |
| DC 电机负极 | → | GND (执行侧) | |

### 5.5 仿真验证
1. PC0 输出高电平 → 光耦 LED 导通 → 光晶饱和 → S8050 导通 → 继电器吸合 → DC 电机转动(表示阀门动作)
2. PC0 输出低电平 → 全部反向 → 电机停止
3. 答辩讲解:"PC0 模拟燃气泄漏检测的报警信号,这条链路保证了电气隔离与故障安全"

## 七、子电路 ⑤ I²C 传感器总线

### 7.1 元件清单
| # | 元件 | Proteus 关键词 | 数量 | 备注 |
|:--:|---|---|:--:|---|
| 1 | 温湿度 DHT22 | `DHT22` | 1 | 代替 SHT40 |
| 2 | 温度 IC LM75 | `LM75` | 1 | 代替 MLX90640(LM75 是 I²C 标准件) |
| 3 | I²C 上拉电阻 | `RES` | 2 | 4.7kΩ |
| 4 | 退耦电容 | `CAP` | 2 | 100nF |

### 7.2 设计要点
- **I²C 总线只需两根线**,可挂载多个不同地址的从设备
- 4.7kΩ 上拉是 I²C 总线**强制要求**(SDA/SCL 都是开漏)
- 真实电路 MLX90640 测温阵列在 Proteus 无对应元件 → **LM75 演示 I²C 通信原理**,讲解时说明"实际产品换 32×24 阵列即可"

### 7.3 接线表
| 信号 | 走向 | 备注 |
|---|---|---|
| STM32 PB6(I2C1_SCL) | → 共享 SCL 总线 | + 4.7kΩ 上拉到 3.3V |
| STM32 PB7(I2C1_SDA) | → 共享 SDA 总线 | + 4.7kΩ 上拉到 3.3V |
| LM75 SCL/SDA | → SCL/SDA 总线 | 地址 0x48 |
| LM75 A0/A1/A2 | → GND | 配置地址 |
| LM75 VCC/GND | → +3.3V / GND | + 100nF 退耦 |
| DHT22 DATA | → STM32 PB8 | DHT22 不是真 I²C,单总线协议 |
| DHT22 VCC/GND | → +3.3V / GND | + 100nF 退耦 |

### 7.4 ASCII 示意图
```
                           +3.3V
                             │
                    ┌────────┼─────────┐
                  [4.7k]   [4.7k]      │
                    │        │         │
   STM32 PB6 SCL ───┴────────┼─────────┼──► LM75 SCL  (地址 0x48)
   STM32 PB7 SDA ────────────┴─────────┼──► LM75 SDA
                                       │
   STM32 PB8     ──────────────────────┴──► DHT22 DATA
```

### 7.5 仿真验证
1. 双击 LM75,在属性里改"Temperature"为 60°C
2. 仿真启动,LCD(若与 ④ 联动)显示 `Pot Temp: 60.0C`
3. 双击 DHT22,改湿度 80% → 显示 `Humidity: 80%`

## 九、H743 ↔ F103 引脚替换对照表(答辩用)

> 评委可能问:"为什么仿真用 F103,实际产品用 H743?" 答:**Proteus 不支持 H7,我们用 F103 演示原理,实际产品的 H7 引脚功能完全等价**(均为 Cortex-M 内核,外设映射相似)。

| 真实 H743 | 仿真 F103 | 功能 |
|---|---|---|
| PA9 / PA10 | PA9 / PA10 | USART1(WiFi 通信) |
| PB6 / PB7 | PB6 / PB7 | I²C1(传感器总线) |
| PB10 / PB11 | PB10 / PB11 | LCD RS/E |
| PA0-PA7 | PA0-PA7 | ADC(气体浓度采集) |
| PC0 | PC0 | 燃气阀控制(GPIO 输出) |
| PB12-PB15 | PB12-PB15 | LCD 数据线 |
| PB0 / PB1 / PB2 | PB0 / PB1 / PB2 | 蜂鸣器/LED 红/LED 黄 |

## 十一、答辩 Q&A 预案

| Q | A |
|---|---|
| 为什么仿真主控不是 H743? | Proteus 不支持 H7 系列,F103 演示原理,真实产品用 H743 跑算力大的图像/雷达任务 |
| 为什么气体传感器用电位器? | Proteus 库 MQ 系列模型不全,电位器输出 0-5V 完美模拟 MQ 模块的模拟输出 |
| 关阀电路为什么这么复杂? | 三层保护:(1)光耦电气隔离 (2)三极管电流放大 (3)二极管续流防反冲,缺一不可 |
| 电磁阀为什么选 NC 常闭? | Fail-Safe 思想——整机断电情况下阀门自动关闭,绝不会出现"断电后燃气一直开"的事故 |
| 多个传感器为何用同一组 I²C? | I²C 是多主多从总线,只需 2 根线 + 每个设备不同地址,**省 GPIO** |
| 仿真没看到摄像头/AI? | 视觉算法运行在 S5P6818 MPU 上,Proteus 不仿真 Linux,实物方案在报告 §4.6 软件架构有详述 |
