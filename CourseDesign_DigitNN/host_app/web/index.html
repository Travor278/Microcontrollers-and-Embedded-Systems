模型演进逻辑

从像素分界线，到能理解局部笔画的卷积结构

这四个模型不是简单堆名字，而是按能力逐级增强：感知机只在 784 个像素上做线性分类；FNN 加入隐藏层和 ReLU， 可以学习像素组合；Tiny-CNN 保留 28 x 28 的二维结构，用 3 x 3 卷积提取边缘、弧线和笔画连接；DS-CNN 再把普通卷积分成 depthwise 与 pointwise 两步，在保持图像特征能力的同时减少 MCU 上的参数和乘加量。

模型怎么选

同一块 STM32 上的速度、精度和资源取舍

答辩时可以把 P/F/C/DS 讲成一条清晰路线：先有最轻的 baseline，再到可用的 FNN，随后用 CNN 提取图像结构，最后用 DS-CNN 面向 MCU 压缩优化。

模型核心思想优势代价
P 感知机 把 28 x 28 拉平成 784 维，直接做线性得分。 最快、最小，适合作为 baseline。 不理解局部笔画，对平移、倾斜和噪声敏感。
F 全连接网络 784 -> 64 -> 10，隐藏层学习像素组合。 结构简单，速度和准确率比较均衡。 仍然丢掉二维空间关系，第一层权重较多。
C Tiny-CNN 3 x 3 卷积提取边缘、弧线和笔画连接。 更适合图像识别，对局部变形更鲁棒。 中间特征图会占 SRAM，卷积计算更复杂。
DS DS-CNN 普通卷积拆成 depthwise 和 1 x 1 pointwise。 结构压缩加 int8 量化，适合 MCU 高效部署。 实现更复杂，通道很少时优势不如中后层明显。
四个模型详解

从线性像素模板，到面向 MCU 的高效卷积

下面四行可以直接作为答辩讲稿：先说明模型做了什么，再说明它在当前工程里的具体结构，最后说明为什么它在准确率、Flash、SRAM 和速度上会表现不同。

w0 w1 w2 w3
Σ
P

感知机：最轻量的线性 baseline

感知机把 28 x 28 图像拉平成 784 维向量，直接计算 10 个类别分数。它本质上是在原始像素空间里给每个数字学习一张“权重模板”：哪些像素亮起来更像 2，哪些像素亮起来更像 8。

公式score_i = sum(x_j * w_ij) + b_i
当前工程784 x 10 + 10 = 7,850 params
优点Flash 最省，推理最快，实现最简单
短板无隐藏层，不理解局部笔画和空间结构

所以它适合作为对照组：如果 P 都能识别，说明预处理和串口闭环没问题；如果 P 不稳，也能反衬 FNN/CNN 的必要性。

F

全连接网络：用隐藏层组合像素模式

FNN 仍然先把图片拉平，但中间加了 64 个隐藏神经元和 ReLU。它不再只看单个像素是否亮，而是能学习“若干像素一起出现时像不像某个笔画组合”。

公式h = ReLU(W1x + b1), score = W2h + b2
当前工程784 -> 64 -> 10, 50,890 params
量化实现int8 weights, int32 bias, FNN_HIDDEN_SHIFT = 8
取舍比 P 准确，但 flatten 后仍丢失二维邻接关系

它是“简单可用”的主力模型：训练和导出都直观，STM32 上也容易解释每一层在做什么。

pool
C

Tiny-CNN：保留图像结构，提取局部笔画

Tiny-CNN 不急着把图像拉平，而是用 3 x 3 卷积核在 28 x 28 图上滑动，先找横线、竖线、弧线、转折点，再把这些局部特征组合成数字类别。

当前工程Conv4 -> Pool14 -> Conv8 -> Pool7 -> FC10
特征长度8 x 7 x 7 = 392 features
参数估算约 4,266 params，比 FNN 少很多
SRAM 压力中间特征图需要 buffer，不只看权重大小

它更“懂图像”：同样一段竖线出现在左侧或右侧，卷积核都能复用，因此对轻微平移和笔画变形更稳。

普通卷积 K² x Cin x Cout
+
DS-CNN K²Cin + CinCout
DS

DS-CNN：把卷积拆开，专门为 MCU 压缩计算

普通卷积同时做“空间特征提取”和“通道混合”。DS-CNN 把它拆成两步：depthwise 每个通道单独做 3 x 3 空间卷积，pointwise 再用 1 x 1 卷积混合通道信息。

参数对比普通卷积 K²CinCout，DS 为 K²Cin + CinCout
结构优势先省乘加量，再配合 int8 量化省 Flash
代码对应run_ds*_depthwise + run_ds*_pointwise
注意点通道太少时优势不明显，中后层更划算

它适合在课程设计里作为进阶亮点：不是盲目加大 CNN，而是用更适合 STM32 的卷积结构换取准确率和资源之间的平衡。

Measure range

Find each layer's max absolute weight and derive one scale.

scale = max(abs(w_float)) / 127
2
Round weights

Divide float weights by scale, round, then clip to [-127, 127].

w_q = clip(round(w_float / scale))
3
Convert bias

Bias is stored as int32 so integer accumulation keeps the original offset.

b_q = round(b_float / (scale_x x scale_w))
4
Run integer MAC

The firmware exports C arrays and uses int32 multiply-accumulate, with shifts between layers.

acc = sum((x_q - zero_x) * w_q) + b_q

量化核心公式 r ≈ scale x (q - zero_point)

真实浮点值 r 不直接存进 STM32，而是拆成一把尺子 scale 和一个整数刻度 q。权重量化常用对称 int8，所以 zero_point = 0。

权重示例 [-0.31, 0.51, 0.70, -0.39]

max(|w|)=0.70，scale=0.70/127≈0.00551，量化后变成 [-56, 93, 127, -71]。

偏置为什么是 int32 b_q = round(b / (scale_x x scale_w))

偏置要和乘加累加值处在同一个数值单位下，才能直接加到 int32 acc 上。

PTQ 与 QAT PTQ: train float -> calibrate -> export int8

当前工程更接近 PTQ：先训练 float32，再导出 int8 权重、int32 偏置和 C 数组。QAT 是训练时模拟量化误差，精度更稳但工程更复杂。

为什么整包不是 4 倍缩小 firmware = model + app + driver + buffers

权重从 float32 到 int8 接近 4 倍压缩，但完整固件还包含触摸屏、串口、LCD、推理代码、量化参数和临时 buffer。

The board build stores weights as int8 and biases as int32. The float number is a parameter-storage estimate; it is shown to explain why quantization is necessary on STM32F103VE.

字母识别三模型

字母固件和数字固件分开烧录

数字固件只包含数字 P / F / C；字母固件只包含字母 P / F / C，不把两个任务域的权重一起带进去。这样报告里能清楚说明 Flash/SRAM 是对应当前任务域的占用。

P

Letter-Perceptron

EMNIST Letters 的线性基线：28 x 28 输入直接映射到 A-Z，体积最小，适合做速度和精度对照。

784 -> 26
F

Letter-FNN

一层隐藏层学习笔画组合，比感知机更能处理弯折和局部组合，是字母固件里的主力全连接模型。

784 -> 96 -> 26
C

Letter-DS-CNN

用 depthwise 逐通道提取局部笔画，再用 1x1 pointwise 混合通道特征；测试集准确率略高于普通 Tiny-CNN，更适合说明嵌入式轻量化。

Conv12 -> DW/PW -> DW/PW -> 26
5000 汉字识别方案

STM32 做手写板，本机做识别

5000 类汉字分类远超 STM32F103VE 的 Flash/SRAM 和算力边界。更合适的闭环是：板端采集轨迹和位图，通过串口发给上位机；本机用 GPU/CPU 模型识别并回显候选字。

首选：MobileNetV3 / EfficientNet 分类器 如果一次只写一个汉字，就把输入统一到 64 x 64 或 96 x 96，输出 5000 类 softmax。训练数据用 CASIA-HWDB 或自建常用字集。
升级：PP-OCRv5 / SVTR 识别器 如果以后要识别一整行中文或混合中英文，直接走 OCR 文本识别模型，比 5000 类单字分类更自然。
API：/api/chinese/infer 网页和板端都只需要把图像或轨迹交给本机 API。现在 API 契约已预留，后续接 PaddleOCR 或自训练模型即可。
