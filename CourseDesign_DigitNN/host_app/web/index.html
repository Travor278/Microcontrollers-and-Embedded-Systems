Flash / SRAM and Quantization
Domain --

1
Measure range

Find each layer's max absolute weight and derive one scale.

scale = max(abs(w_float)) / 127
2
Round weights

Divide float weights by scale, round, then clip to [-127, 127].

w_q = clip(round(w_float / scale))
3
Convert bias

Bias is stored as int32 so integer accumulation keeps the original offset.

b_q = round(b_float * input_scale / scale)
4
Run integer MAC

The firmware exports C arrays and uses int32 multiply-accumulate, with shifts between layers.

score = sum(x_u8 * w_q) + b_q

The board build stores weights as int8 and biases as int32. The float number is a parameter-storage estimate; it is shown to explain why quantization is necessary on STM32F103VE.

字母识别三模型

字母固件和数字固件分开烧录

数字固件只包含数字 P / F / C；字母固件只包含字母 P / F / C，不把两个任务域的权重一起带进去。这样报告里能清楚说明 Flash/SRAM 是对应当前任务域的占用。

P

Letter-Perceptron

EMNIST Letters 的线性基线：28 x 28 输入直接映射到 A-Z，体积最小，适合做速度和精度对照。

784 -> 26
F

Letter-FNN

一层隐藏层学习笔画组合，比感知机更能处理弯折和局部组合，是字母固件里的主力全连接模型。

784 -> 96 -> 26
C

Letter-Tiny-CNN

用 8/16 通道卷积提取局部笔画、拐点和闭合区域，适合区分 B/R、C/G、I/L 等容易混淆的字母。

Conv8 -> Conv16 -> 26
5000 汉字识别方案

STM32 做手写板，本机做识别

5000 类汉字分类远超 STM32F103VE 的 Flash/SRAM 和算力边界。更合适的闭环是：板端采集轨迹和位图，通过串口发给上位机；本机用 GPU/CPU 模型识别并回显候选字。

首选：MobileNetV3 / EfficientNet 分类器 如果一次只写一个汉字，就把输入统一到 64 x 64 或 96 x 96，输出 5000 类 softmax。训练数据用 CASIA-HWDB 或自建常用字集。
升级：PP-OCRv5 / SVTR 识别器 如果以后要识别一整行中文或混合中英文，直接走 OCR 文本识别模型，比 5000 类单字分类更自然。
API：/api/chinese/infer 网页和板端都只需要把图像或轨迹交给本机 API。现在 API 契约已预留，后续接 PaddleOCR 或自训练模型即可。
